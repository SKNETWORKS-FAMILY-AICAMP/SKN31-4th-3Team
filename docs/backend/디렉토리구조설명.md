# 각 주요 구성 요소 역할
## <Backend 프로젝트 디렉토리 구조>
```
Django_backend/      ← 루트 디렉토리 (Project Root Directory)
├── manage.py           ← 관리용 CLI 스크립트
├── config/                 ← 프로젝트 패키지 (settings.py 등)
├── users/                  ← 회원 & 인증 앱
│   ├── models.py
│   ├── views.py
│   └── ...
├── chat/                   ← 대화방 & 메시지 CRUD 앱
│   ├── models.py
│   ├── views.py
│   └── ...
└── llm_core/               ← LLM 연동 & 스트리밍 전용 앱
    ├── services.py (생성 예정)
    ├── views.py
    └── ...
```
## 1. 최상위 Django_backend/ (루트 디렉토리)

- 프로젝트의 전체 컨테이너 역할을 하는 폴더입니다.

- 폴더명은 자유롭게 변경해도 Django 동작에 영향을 주지 않으며, Git 저장소의 최상위 폴더가 되는 경우가 많습니다.

## 2. manage.py

- Django 프로젝트를 관리하기 위해 사용하는 커맨드라인(CLI) 도구입니다.

- 서버 실행(python manage.py runserver), 마이그레이션(python manage.py makemigrations), 앱 생성(python manage.py startapp) 등 개발에 필수적인 명령을 실행할 때 사용합니다.

## 3. config/ (프로젝트 패키지)

- 실제 파이썬 코드로서 import되는 최상위 파이썬 패키지입니다.

- Django_backend.settings와 같이 참조되므로 이 폴더의 이름은 변경하지 않는 것이 좋습니다.

### settings.py

- 프로젝트의 모든 환경 설정(DB 연결 정보, Installed Apps, Middleware, CORS, 보안 키 등)이 모여있는 핵심 파일입니다.

### urls.py

- 프로젝트의 최상위 URL 진입점(URLconf)입니다.

- 사용자가 요청한 URL 주소와 View(처리 로직)를 연결해주는 라우팅 규칙을 정의합니다.

### asgi.py (Asynchronous Server Gateway Interface)

- 비동기 웹 서버(Uvicorn, Daphne 등)와 Django를 연결하기 위한 표준 진입점입니다.

- LLM 토큰 단위 스트리밍(SSE), WebSocket 등 비동기 처리가 필요한 기능을 구현할 때 주로 활용됩니다.

### wsgi.py (Web Server Gateway Interface)

- 전통적인 동기 방식의 웹 서버(Gunicorn, Nginx 등)와 Django를 연결하기 위한 표준 진입점입니다.

## <APP 및 설명>
- Django_Backend 프로젝트에서 앱(App)을 분리할 때, "하나의 앱은 하나의 핵심 기능/도메인만 담당한다는"원칙을 따릅니다.

| 앱 이름 (App Name) | 담당 주요 기능 (Domain Scope) | 주요 파일 및 역할 |
| :--- | :--- | :--- |
| **`users`** | 회원 관리 및 인증 (Auth) | • Custom User 모델 (`AbstractUser`)<br>• JWT 로그인 / 회원가입 / 토큰 재발급 API |
| **`chat`** | 대화 데이터 모델링 및 REST API | • `ChatSession`, `ChatMessage` ORM 모델<br>• 대화방 CRUD, 과거 대화 내역 조회 API |
| **`llm_core`** | LLM 파이프라인 및 스트리밍 | • OpenAI / LangChain API 연동 로직<br>• SSE(Server-Sent Events) 스트리밍 응답 API<br>• 프롬프트 템플릿 및 맥락(Context) 조립 |

* chat과 llm_core를 분리하는 이유  

    * chat 앱: 단순히 데이터베이스(DB)와의 CRUD 작업(대화방 이름 변경, 대화목록 가져오기 등)에 집중합니다.

    * llm_core 앱: OpenAI API 호출, LangChain 프롬프트 빌드, SSE 스트리밍 처리 등 외부 AI와의 통신/비즈니스 로직을 전담합니다.

    * 이렇게 분리해 두면 추후 LLM 모델을 OpenAI에서 Claude나 Local LLM으로 변경하거나 RAG(Vector DB)를 도입할 때, DB 구조(chat) 건드릴 필요 없이 llm_core 부분만 깔끔하게 수정할 수 있어 유지보수가 훨씬 쉬워집니다.
