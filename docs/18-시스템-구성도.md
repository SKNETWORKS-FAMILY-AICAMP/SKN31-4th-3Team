# 시스템 구성도

Zone 별로 나누고, **동기 REST 와 비동기 SSE 를 선으로 구분**한다.

```
범례   ──▶  HTTP REST (동기, 요청-응답)
       ══▶  SSE EventStream (비동기, 지속 연결)
       ┄┄▶  내부 프로토콜 (Bolt / Postgres wire)
```

## 2. 데이터 흐름 — 두 갈래

### 2.1 동기 REST — 질문 → 구절

```
브라우저 ──▶ nginx ──▶ Django AskView
                          │
                          ├─▶ intents.match_intent()        주제 추출
                          ├─▶ Ollama /api/embed             질문 임베딩
                          ├─▶ RDS  ORDER BY <=> LIMIT 60    벡터 후보
                          ├─▶ tone 게이트                    경고 제외
                          ├─▶ Neo4j graph.boost()           감정 가산점
                          └─▶ 상위 3개 + 공감·묵상
                          │
브라우저 ◀────────────────┘  JSON (한 번에)
```

**타임아웃 15초.** 넘으면 `TimeoutError` — 사용자에게 "응답이 늦어 멈췄습니다".

### 2.2 비동기 SSE — 상담 대화

```
브라우저 ══▶ nginx ══▶ Django ChatStreamView
                          │
                          ├─▶ chat.context.for_session()    씨앗 구절 + 그래프 인물
                          │     └─▶ Neo4j theme_witnesses()
                          ├─▶ prompts.build_system_prompt() 3층 조립
                          └─▶ LangChain ══▶ OpenAI (stream)
                                              │
                          ┌───────────────────┘ 조각
                          ▼
브라우저 ◀══ data: {"content": "그"}
브라우저 ◀══ data: {"content": "말씀"}
브라우저 ◀══ data: [DONE]
                          │
                          └─▶ RDS  ChatMessage 저장 (전체 답변)
```

**타임아웃 없음.** 긴 답변은 연결이 오래 열려 있는 것이 정상이다.
대신 화면을 떠나면 `AbortController` 로 끊는다.

> ⚠️ **nginx `proxy_buffering`** — 현재 기본값(`on`)이다. 조각이 모였다가
> 나갈 수 있다. `proxy_buffering off;` 추가는 `docs/14` 의 C-1 참조.

## 3. 배포 아키텍처

```
클라이언트 :80
     │
     ▼
nginx 1.27 (컨테이너 web)
  ├─ 정적 파일 직접 서빙  (React 빌드 산출물)
  ├─ SPA 폴백            (try_files → index.html)
  └─ /api/ 프록시 ──────▶ gunicorn (컨테이너 api)
                              │  WSGI
                              ▼
                          Django 5.2
```

**gunicorn 워커 5개** — g4dn.xlarge 는 4 vCPU. `(2×vCPU)+1 = 9` 는 과하고,
작업이 임베딩·LLM 대기 위주라 I/O 바운드다.

**WSGI 를 쓴다** — SSE 는 `StreamingHttpResponse` 로 WSGI 에서도 된다.
ASGI 로 올리면 uvicorn·비동기 ORM 등 바꿀 것이 늘어나는데, 지금 필요한
동시성 수준이 아니다.

**Ollama 를 컨테이너에 넣지 않는다** — GPU 를 컨테이너로 넘기려면
`nvidia-container-toolkit` 이 한 겹 더 붙는다. 발표 전날 깨질 수 있는
곳을 하나 더 만들지 않는다. `extra_hosts: host.docker.internal:host-gateway`
로 호스트의 Ollama 에 닿는다.

## 4. 보안 경계

```
┌─ 경계 1 · AWS 보안 그룹 ─────────────────────────────┐
│  eden-web-sg   80 ← 0.0.0.0/0                        │
│                22 ← 내 IP 만                          │
│  eden-db-sg  5432 ← eden-web-sg (IP 아님, 보안 그룹)  │
│  ┌─ 경계 2 · nginx ──────────────────────────────┐   │
│  │  정적/API 경로 분리                            │   │
│  │  ┌─ 경계 3 · Django ────────────────────────┐ │   │
│  │  │  ALLOWED_HOSTS · CSRF_TRUSTED_ORIGINS    │ │   │
│  │  │  JWT (SimpleJWT) · IsAuthenticated       │ │   │
│  │  │  queryset 을 request.user 로 필터        │ │   │
│  │  │  ┌─ 경계 4 · 비밀 ────────────────────┐  │ │   │
│  │  │  │  .env.prod (gitignore, chmod 600)  │  │ │   │
│  │  │  │  SECRET_KEY · DB · OpenAI · Neo4j  │  │ │   │
│  │  │  └────────────────────────────────────┘  │ │   │
│  │  └──────────────────────────────────────────┘ │   │
│  └───────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────┘
```

**보안 그룹으로 지정하는 이유** — RDS 인바운드를 IP 로 열면 EC2 를 다시
만들 때마다 규칙을 고쳐야 한다.

**미적용** — HTTPS. 도메인이 없어 IP 로는 인증서를 발급할 수 없다.

## 5. 컨테이너 구성

| 컨테이너 | 이미지 | 포트 | 재시작 |
|---|---|---|---|
| `web` | `frontend/Dockerfile` (node build → nginx) | 80:80 | unless-stopped |
| `api` | `server/Dockerfile` (python + gunicorn) | expose 8000 | unless-stopped |

**호스트 프로세스** — Ollama (systemd, `OLLAMA_HOST=0.0.0.0:11434`,
`OLLAMA_KEEP_ALIVE=-1`)

**로컬과 배포를 두 파일로 나눈다** — 로컬은 DB 를 컨테이너로 띄우고 배포는
RDS 를 쓴다. 한 파일에 프로필로 섞으면 "지금 어느 쪽이 도는지" 를 매번
확인해야 하고, 그 확인을 한 번 빼먹으면 배포에서 로컬 DB 가 뜬다.

## 6. 확장 여지

| 구간 | 지금 | 늘리려면 |
|---|---|---|
| API | gunicorn 5 워커 | ALB + EC2 여러 대 |
| 임베딩 | EC2 GPU 1대 | 별도 추론 서버로 분리 |
| DB | RDS 단일 AZ | 다중 AZ + 읽기 복제본 |
| 정적 | nginx 직접 | S3 + CloudFront |
| 무거운 작업 | 없음 | Celery + Redis (뼈대만 있음) |
| 배포 | `deploy.sh` | GitHub Actions |

## 7. 장애 시 동작

| 죽는 것 | 결과 |
|---|---|
| **Neo4j Aura** | 가산점 0, 인물 맥락 없음. 검색·상담은 정상 |
| **Ollama** | 주제 사전 기반 추천으로 폴백. 화면 정상 |
| **OpenAI** | 상담만 실패. 구절 탐색은 정상 |
| **RDS** | 전면 장애 (여기만 단일 실패점) |
| **api 컨테이너** | `restart: unless-stopped` 로 자동 복구 |
| **EC2 재시작** | 탄력적 IP 유지. 컨테이너 자동 기동. **Ollama 예열 필요** |

> 단일 실패점이 RDS 하나뿐이도록 설계했다. 나머지는 전부 없어도 화면이 돈다.
