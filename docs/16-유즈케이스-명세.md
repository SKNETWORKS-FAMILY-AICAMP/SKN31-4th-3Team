# 유즈케이스 명세

각 유즈케이스는 **주요 흐름 · 대체 흐름 · 예외 흐름** 세 단으로 적는다.
예외 흐름이 빠지면 개발자와 테스터가 서로 다른 것을 상상하게 된다.

## 액터

| 액터 | 설명 |
|---|---|
| 방문자 | 로그인하지 않은 사람. 질문·탐색까지 가능 |
| 사용자 | 로그인한 사람. 상담 저장·이어보기 가능 |
| 시스템 | Django + LLM + 벡터DB + 그래프DB |
| 외부 | OpenAI · Ollama · Neo4j Aura |

## 목록

| ID | 이름 | 액터 |
|---|---|---|
| UC-01 | 회원가입과 로그인 | 방문자 |

| UC-07 | 회원정보를 고치거나 탈퇴한다 | 사용자 |

## UC-01 · 회원가입과 로그인

**선행조건** 없음
**후행조건** Access/Refresh 토큰이 브라우저에 저장된다

### 주요 흐름

1. 방문자가 계정 화면에서 "회원가입" 을 고른다
2. 이름 · 이메일 · 비밀번호 · **MBTI 16칸 중 하나**를 입력한다
3. 시스템이 이메일 중복과 비밀번호 규칙을 검사한다
4. 계정을 만들고 곧바로 로그인 상태로 만든다
5. 원래 가려던 화면으로 돌려보낸다 (`?then=`)

### 대체 흐름

- **1a. 이미 계정이 있다** → "로그인" 으로 전환. 입력값은 유지
- **2a. MBTI 를 모른다** → 건너뛸 수 있다. 은하 추천이 주제만 보고 이뤄진다
- **5a. `then` 이 없다** → 홈으로

### 예외 흐름

| # | 상황 | 시스템 동작 |
|---|---|---|
| 3a | 이메일 중복 | 필드 아래 "이미 가입된 이메일입니다". 다른 입력은 유지 |
| 3b | 비밀번호 규칙 미달 | 어떤 규칙인지 밝힌다 |
| 4a | 서버 500 | "가입하지 못했습니다" + 원인 문구. 다시 시도 |
| 4b | **네트워크 끊김** | "연결이 끊어졌습니다. 네트워크를 확인해 주세요" |
| 4c | **15초 초과** | "응답이 늦어 멈췄습니다. 잠시 뒤 다시 시도해 주세요" |
| ※ | `then` 이 외부 주소 | `internalPath()` 가 걸러 홈으로 (오픈 리다이렉트 방지) |

### 토큰 갱신 (배경 흐름)

1. 요청이 401 을 받는다
2. Refresh 로 새 Access 를 받아 **원래 요청을 한 번만** 다시 보낸다
3. 동시에 여러 요청이 만료를 만나면 **갱신은 한 번**만 하고 함께 기다린다

- **2a. Refresh 도 만료** → 로그아웃하고 로그인 화면으로
- **2b. 선택적 인증 경로** → 익명으로 물러서서 다시 보낸다 (입구를 막지 않는다)
- **2c. 사라진 사용자의 토큰** → 서버가 500 이 아니라 401 로 답한다

## UC-02 · 고민을 묻고 구절을 받는다

**선행조건** 없음 (로그인 불필요)
**후행조건** 공감 · 묵상 · 구절 3개 · 추천 은하가 화면에 있다

### 주요 흐름

1. 방문자가 홈 입력창에 고민을 적는다
2. 시스템이 질문에서 **감정 주제**를 뽑는다
3. 질문을 임베딩해 pgvector 에서 **후보 60개**를 건진다
4. 성격(경고 제외) → 주제 일치 → **그래프 가산점** 순으로 점수를 매긴다
5. 상위 3개 구절과 공감·묵상 문구를 보낸다
6. 화면이 구절 카드와 "은하 찾아가기" 를 띄운다

### 대체 흐름

- **1a. 추천 질문 칩을 누른다** → 그 문장이 입력되어 바로 3번으로
- **1b. 로그인 상태** → MBTI 가 은하 추천에 반영된다
- **6a. "다른 구절 보기"** → 순위에서 다음 3개. 끝에 닿으면 처음으로 돌아온다

### 예외 흐름

| # | 상황 | 시스템 동작 |
|---|---|---|
| 2a | 주제를 못 찾음 | 벡터 결과만으로 진행. 그래프 가산점은 건너뛴다 |
| 3a | **임베딩 모델 미응답** | 주제 사전 기반 추천으로 물러선다. 화면은 그대로 |
| 3b | pgvector 없음 / 임베딩 비어 있음 | 위와 같은 폴백 |
| 4a | **Neo4j 끊김·지연** | 가산점 0. 벡터+주제+성격으로만 고른다. 사용자는 모른다 |
| 5a | **15초 초과** | "응답이 늦어 멈췄습니다" + 다시 시도 |
| 5b | 네트워크 끊김 | "연결이 끊어졌습니다" |
| ※ | **위기 신호 감지** | → UC-06 으로 분기. 구절 추천을 하지 않는다 |

## UC-03 · 은하수를 탐색해 구절을 연다

**선행조건** 없음
**후행조건** 구절 상세가 열려 있다

### 주요 흐름

1. 방문자가 별자리 화면에 들어간다
2. 빈 곳을 끌어 시점을 돌린다
3. 별 하나를 누른다
4. 카메라가 **1.6초 동안 그 별로 날아간다** (방향감 스트리킹)
5. 도착하면 구절 상세가 열린다 — 구절 · 맥락 · 묵상 · "상담 이어가기"

### 대체 흐름

- **1a. 인트로에서 넘어옴** → 창세기 문장이 흐르고 별이 은하로 모인 뒤
- **1b. 답변 화면의 "은하 찾아가기"** → 그 은하로 날아가 **별이 상징으로 모인다**
  → "상담 들어가기" 를 누르면 대화로
- **3a. 은하(성운)를 누름** → 열지 않고 그 은하를 화면 중앙으로 데려온다
- **3b. 사이드바 → 구절 목록 창** → 은하 탭에서 고르면 같은 비행
- **3c. 키보드** → 방향키로 순회, Enter 로 선택 (같은 비행)
- **2a. MBTI 를 고름** → 가까운 은하가 강조된다

### 예외 흐름

| # | 상황 | 시스템 동작 |
|---|---|---|
| 1a | 캔버스 미지원 브라우저 | 목록 기반 대체 화면 |
| 1b | 저사양 — FPS 저하 | 별 수·효과를 자동으로 낮춘다 |
| 1c | **모션 축소 설정** | 비행·반짝임을 끄고 즉시 전환 |
| 3a | 구절 목록을 못 받음 | "구절을 불러오지 못했습니다" + 다시 시도 |
| 5a | 없는 구절 id 로 직접 진입 | 하늘에 머물고 상세를 열지 않는다 |

### 모바일 시나리오

- 720px 미만 — 오른쪽 MBTI 레일이 접힌다. 목록으로 같은 탐색 가능
- 세로 620px 미만 — 레일이 접히고 화면 폭을 돌려준다
- 사이드바는 화면을 밀지 않고 **위에 겹친다** (캔버스 구도가 틀어지지 않게)
- 터치에는 hover 가 없으므로 복사 버튼이 항상 옅게 보인다

## UC-04 · 상담을 이어간다

**선행조건** 로그인
**후행조건** 대화가 서버에 저장된다

### 주요 흐름

1. 사용자가 구절 상세나 답변 화면에서 "상담 이어가기" 를 누른다
2. 시스템이 대화방을 만들고 **인물을 배정**한다 (질문 주제 + MBTI)
3. 그 인물의 첫 인사가 즉시 뜬다 (LLM 을 부르지 않는다)
4. **고른 주제가 첫 질문으로 자동 전송된다**
5. 서버가 프롬프트를 조립한다 — 공통 규범 + 관계 + 페르소나 + **씨앗 구절 + 그래프 인물**
6. 답변이 **글자 단위로 흘러온다** (SSE)
7. 완료되면 복사 버튼이 나타난다
8. 사용자가 이어서 말한다 → 5~7 반복

### 대체 흐름

- **1a. 은하를 직접 골랐다** → 그 인물이 이긴다. 배정 이유는 비운다
- **2a. 인물 미지정** → 서버가 주제로 고르고 "왜 이 인물인지" 한 줄을 붙인다
- **4a. 씨앗 질문이 없다** (구절에서만 진입) → 자동 전송 없음. 빈 입력칸
- **5a. 첫 답변** → 인물 이름을 꺼내지 않는다. 듣는 것이 먼저
- **5b. 두 번째 답변부터** → 그래프가 준 인물 한 사람을 실제로 꺼낸다
- **6a. 스트리밍이 막힌 환경** → 한 번에 받는 경로로 물러선다

### 예외 흐름

| # | 상황 | 시스템 동작 |
|---|---|---|
| 2a | 대화방 생성 실패 | "대화를 시작하지 못했습니다" + 원인 + 다시 시작 |
| 5a | **OpenAI 키 없음/잔액 초과** | "답변을 받지 못했습니다" + 서버 원인 문구 |
| 6a | **SSE 연결 끊김** | 받은 데까지 남기고 "다시 시도" 를 보여 준다 |
| 6b | **화면을 떠남** | 진행 중인 스트림을 즉시 끊는다 (조각이 밀려들지 않게) |
| 6c | 새 질문을 보냄 | 이전 스트림을 끊고 새로 연다 |
| 4a | Neo4j 끊김 | 인물 없이 진행. 답이 조금 덜 풍부해질 뿐 |
| ※ | **위기 신호** | → UC-06. LLM 을 기다리지 않는다 |
| ※ | 로그인 안 함 | 로그인 화면으로. 돌아올 곳을 `?then=` 에 담는다 |

## UC-05 · 지난 상담을 다시 본다

**선행조건** 로그인 + 대화 1개 이상

### 주요 흐름

1. 왼쪽 위 메뉴로 사이드바를 연다
2. "지난 상담" 목록에서 하나를 고른다
3. 서버에서 메시지를 받아 되살린다
4. 이어서 대화한다

### 대체 흐름

- **2a. 대화가 없다** → "이야기를 시작하면 여기에 남습니다"
- **2b. ✕ 로 나가기** → 그 자리에서 "지우기 / 취소" 로 한 번 더 묻는다
- **3a. 서버가 없는 환경** → 브라우저 저장에서 되살린다

### 예외 흐름

| # | 상황 | 시스템 동작 |
|---|---|---|
| 3a | 남의 대화 id | 서버가 목록 자체를 사용자로 걸러 접근이 불가능하다 |
| 3b | 다른 브라우저에서 만든 대화 (서버 없는 환경) | "이 브라우저에 남아 있지 않은 대화입니다" |
| 3c | 불러오기 실패 | "이 대화를 불러오지 못했습니다" + 원인 |
| ※ | 이어보기에서는 **씨앗 질문을 다시 보내지 않는다** | 같은 말을 두 번 한 대화가 되지 않게 |

## UC-06 · 위기 신호에 안전 안내를 받는다

> 이 유즈케이스는 **다른 모든 흐름보다 우선**한다.

### 주요 흐름

1. 사용자가 자해·자살·학대·급성 위기를 시사하는 말을 한다
2. **프론트엔드가 먼저 판정한다** — 서버 왕복을 기다리지 않는다
3. 안전 안내를 즉시 붙인다
4. 구절 추천이나 일반 상담 응답을 하지 않는다

### 대체 흐름

- **2a. 프론트가 못 잡고 서버로 감** → 프롬프트의 안전 규칙이 두 번째 그물
- **4a. 사용자가 대화를 이어감** → 안전 태도를 유지한 채 이어간다

### 예외 흐름

| # | 상황 | 시스템 동작 |
|---|---|---|
| 2a | **서버가 죽어 있다** | 그래도 안내는 뜬다. 이것이 프론트 판정을 둔 이유 |
| 2b | 오탐 (문학적 표현 등) | 사용자가 대화를 이어갈 수 있다. 막지 않는다 |

### 설계 원칙

- 상태를 심문하듯 되묻지 않는다
- 안전을 확인하는 것이 위로보다 먼저다
- 페르소나 연기와 안전이 부딪히면 **연기를 멈춘다**

## UC-07 · 회원정보를 고치거나 탈퇴한다

### 주요 흐름

1. 우측 상단 계정 칩이나 사이드바 하단에서 계정 화면으로 간다
2. 이름 · MBTI 를 고치고 저장한다
3. 저장 결과를 알린다

### 대체 흐름

- **2a. 탈퇴** → 두 단계로 확인한다
- **2b. 로그아웃** → 토큰을 지우고 홈으로

### 예외 흐름

| # | 상황 | 시스템 동작 |
|---|---|---|
| 2a | 저장 실패 | 입력값을 유지한 채 원인을 알린다 |
| 2b | **탈퇴** | 대화 기록이 CASCADE 로 함께 지워진다. 되돌릴 수 없음을 미리 밝힌다 |
| 2c | 만료된 토큰 | 자동 갱신 후 재시도. 갱신도 실패하면 로그인으로 |
