## 2. ⚠️ 고친 것 — 서버가 뜨지 않는 문제

`llm_core/services.py` 최상단에 이 줄이 있었습니다.

```python
client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))
```

**`OpenAI(api_key=None)` 은 생성하는 순간 예외를 던집니다.** 확인했습니다:

```
OpenAIError: Missing credentials. Please pass an `api_key` ...
```

이 파일은 `chat/views → chat/urls → config/urls` 로 이어지는 import 사슬 위에 있습니다.
즉 **OpenAI 키가 없으면 Django 자체가 뜨지 않습니다.** 로그인도, 회원가입도,
은하 목록도 전부 막힙니다. 실제로 `manage.py check` 가 이 지점에서 죽었습니다.

### 조치 — 클라이언트를 지연 생성으로

```python
def get_client() -> OpenAI:
    global _client
    if _client is None:
        api_key = getattr(settings, "OPENAI_API_KEY", "") or None
        if not api_key:
            raise RuntimeError("OPENAI_API_KEY 가 설정되지 않았습니다...")
        _client = OpenAI(api_key=api_key)
    return _client
```

키가 없어서 막혀야 하는 것은 **LLM 답변 생성 하나뿐**입니다.
지금은 키 없이도 서버가 뜨고, 스트리밍을 호출했을 때만 오류가 흐릅니다.

```
POST stream (키 없음)  200  data: {"error": "LLM 스트리밍 실패: OPENAI_API_KEY 가 설정되지 않았습니다."}
```

두 함수의 동작은 그대로입니다. 모델명(`gpt-4o-mini`)만 상수로 모았습니다 —
두 함수가 각자 문자열을 들고 있으면 한쪽만 바꾸는 일이 반드시 생깁니다.

## 3. 보존한 것 — 팀 settings.py 를 그대로 덮지 않은 이유

받은 `settings.py` 를 그대로 쓰면 아래가 사라집니다. 전부 **되돌리면 고장 나는** 항목이라 유지했습니다.

| 항목 | 팀 파일 | 유지한 값 | 없으면 |
|---|---|---|---|
| `scripture` 앱 | 없음 | 유지 | 은하·구절 API 전멸 (프론트가 호출 중) |
| `SECRET_KEY` | 기본값 없음 | `default=` 있음 | `.env` 없으면 `git clone` 후 즉시 크래시 |
| `DATABASE_URL` | 기본값 없음 | SQLite 폴백 | 위와 같음 |
| `ALLOWED_HOSTS` | `[]` | env 로 주입 | `DEBUG=False` 로 켜면 전 요청 400 |
| `STATIC_ROOT` | 없음 | 유지 | `collectstatic` 실패 |
| `DEFAULT_AUTO_FIELD` | 없음 | 유지 | 매 `makemigrations` 마다 W042 경고 |
| Throttle / Pagination | 없음 | 유지 | API 남용 제한 없음 |
| `SECURE_PROXY_SSL_HEADER` | 없음 | 유지 | ALB 뒤에서 HTTPS 인식 실패 |

**`users/views.py` 도 유지했습니다.** 받은 `serializers.py` 에는 `UserUpdateSerializer` 가
없는데, `UserSerializer` 는 `read_only_fields = fields` 입니다. 그대로 PATCH 에 쓰면
**200 을 돌려주면서 값은 바뀌지 않습니다** — 화면에서는 저장된 것처럼 보이고
새로고침하면 되돌아갑니다. 가장 찾기 어려운 종류의 버그라, 수정 전용
serializer 를 별도로 두었습니다.

## 4. 프론트에서 맞춘 것

### ① 대화 시작 — `/chat/threads/` 가 사라졌습니다

세션 생성으로 바꿨습니다.

```
POST /api/v1/chat/sessions/  { title }   →  { id }
```

첫 인사는 **화면에서 만듭니다.** 서버에서 받으려면 LLM 을 한 번 더 호출해야 하고,
그 시간만큼 사용자는 빈 화면을 봅니다. 이 인사는 DB 에 저장되지 않습니다 —
대화를 다시 열면 실제로 주고받은 말만 남습니다. 맞는 동작입니다.

### ② SSE 수신 — 라이브러리 없이

가이드는 `@microsoft/fetch-event-source` 를 권했지만 쓰지 않았습니다.

- 그 라이브러리에서 우리가 필요한 것은 **"청크를 줄 단위로 자르는 것"** 하나입니다
- **자동 재연결은 오히려 해롭습니다.** 답변이 반쯤 나오다 끊겼을 때 다시 요청하면
  같은 질문이 두 번 저장되고 서버는 답변도 두 번 만듭니다
- `services/sse.ts` 40줄로 충분합니다

가장 중요한 처리는 **청크 경계가 줄 경계와 다르다**는 점입니다.
네트워크는 `data: {"con` 처럼 아무 데서나 끊어 줍니다. 버퍼에 이어 붙였다가
개행이 나올 때만 잘라야 하고, 한글은 3바이트라 `TextDecoder` 를 stream 모드로
써야 합니다. **짧은 답변에서는 멀쩡하다가 긴 답변에서만 가끔 깨지는** 종류라
테스트로 못박아 두었습니다.

### ③ 말풍선 하나에 글자가 자라게

`stream/started` 로 **빈 말풍선을 먼저 세우고** `stream/chunk` 로 이어 붙입니다.
조각마다 말풍선을 만들면 한 답변이 열 개로 쪼개집니다.

화면을 떠나면 `AbortController` 로 읽기를 멈춥니다. 멈추지 않으면 사라진
대화에 조각이 계속 밀려 들어옵니다.

## 5. 아직 다른 것 — 확인 부탁드립니다

### ① 메시지 목록이 페이지네이션됩니다

```jsonc
GET /api/v1/chat/sessions/1/messages/
{ "count": 0, "next": null, "previous": null, "results": [] }
```

우리 쪽 `PAGE_SIZE: 50` 설정 때문입니다. 프론트는 아직 이 목록을 읽지 않아
지금은 문제가 없지만, **대화 이어보기를 붙일 때 `results` 를 꺼내야 합니다.**
그때 다시 짚겠습니다.

### ② `scripture` 앱을 계속 쓸 것인지

은하 13개와 구절 702개를 주는 API 입니다. 팀 `settings.py` 에는 없었는데,
빼려던 것인지 그냥 그 파일에 없었던 것인지 확인이 필요합니다.
**지금은 유지했고, 프론트가 이 경로를 호출하고 있습니다.**

### ③ 시드 데이터가 비어 있습니다

```
GET /api/v1/scripture/galaxies/  →  []
```

적재 명령을 돌려야 합니다.

```bash
cd server && python manage.py loaddata scripture/fixtures/galaxies.json scripture/fixtures/verses.json
```

## 7. 붙이는 방법

```bash
# 서버
cd server
cp .env.example .env          # SECRET_KEY, OPENAI_API_KEY 채우기
python manage.py migrate
python manage.py runserver

# 프론트
cd frontend
echo "VITE_API_BASE_URL=http://localhost:8000" > .env.local
npm run dev
```

`.env.local` 이 없으면 프론트는 mock 으로 돕니다 — 서버 없이도 화면 전체가
그대로 동작합니다. 발표 당일 백엔드에 문제가 생겨도 데모는 살아 있습니다.
