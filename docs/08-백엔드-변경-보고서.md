## 1. 고장 났던 것 3가지

### ① OpenAI 키가 없으면 서버가 통째로 안 뜬다

**파일** `llm_core/services.py`

받은 코드의 최상단에 이 줄이 있었습니다.

```python
client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))
```

`OpenAI(api_key=None)` 은 **생성하는 순간** 예외를 던집니다.

```
OpenAIError: Missing credentials. Please pass an `api_key` ...
```

이 파일은 `chat/views → chat/urls → config/urls` 로 이어지는 import 사슬 위에
있습니다. 그래서 키가 없으면 **Django 자체가 부팅에 실패**합니다.
로그인도, 회원가입도, 은하 목록도 전부 막힙니다.
실제로 `manage.py check` 가 이 지점에서 죽었습니다.

**조치 — 클라이언트를 지연 생성으로 바꿨습니다.**

```python
def get_client() -> OpenAI:
    global _client
    if _client is None:
        api_key = getattr(settings, "OPENAI_API_KEY", "") or None
        if not api_key:
            raise RuntimeError("OPENAI_API_KEY 가 설정되지 않았습니다...")
        _client = OpenAI(api_key=api_key)
    return _client
```

키가 없어서 막혀야 하는 것은 **LLM 답변 생성 하나뿐**입니다.
지금은 키 없이도 서버가 뜨고, 스트리밍을 호출했을 때만 오류가 흐릅니다.

두 함수의 동작은 그대로입니다. 모델명(`gpt-4o-mini`)만 상수로 모았습니다 —
두 함수가 각자 문자열을 들고 있으면 한쪽만 바꾸는 일이 반드시 생깁니다.

---

### ② 브라우저에서만 대화가 실패한다 (406)

**파일** `llm_core/negotiation.py` (신규), `chat/views.py`

DRF 는 핸들러를 부르기 **전에** `Accept` 헤더를 보고 응답 렌더러를 고릅니다.
기본 렌더러는 JSON 뿐이라, 브라우저가 SSE 규격대로
`Accept: text/event-stream` 을 보내면 **406 Not Acceptable** 로 막힙니다.
`post()` 는 실행조차 되지 않습니다.

나란히 재현한 결과입니다.

```
① Accept 없음                 → 200
② Accept: text/event-stream  → 406 "요청 Accept 헤더를 만족시킬 수 없습니다."
```

**Accept 헤더 없이 부르면 통과하기 때문에 curl · Swagger · 테스트 클라이언트로는
멀쩡하고 브라우저에서만 실패합니다.** 이것 때문에 한참 헤맸습니다.

**조치 — 이 엔드포인트만 콘텐츠 협상을 건너뛰게 했습니다.**

```python
class ChatStreamView(APIView):
    renderer_classes = [EventStreamRenderer]
    content_negotiation_class = IgnoreClientContentNegotiation
```

> **프론트에서 Accept 헤더를 빼는 방법도 있었지만 택하지 않았습니다.**
> 그건 "규격대로 보내면 깨지는 API" 를 남겨 두는 것입니다.
> 다음 사람이 표준대로 짜면 또 막힙니다.

---

### ③ 같은 이름으로는 두 번째 사람이 가입할 수 없다

**파일** `users/models.py`

`AbstractUser` 의 `username` 은 기본이 `unique=True` 입니다.
로그인 ID 로 쓸 때는 맞는 설계지만, 우리는 `USERNAME_FIELD` 가 email 이고
이 값은 화면에서 **"○○님, 어서 오세요"** 로 부르는 호칭일 뿐입니다.

```
1번째 "지훈" 가입: 201
2번째 "지훈" 가입: 400 {"username":["해당 사용자 이름은 이미 존재합니다."]}
```

발표 자리에서 두 명이 시연하면 바로 터졌을 겁니다.

**조치 —** `username = models.CharField(max_length=150, unique=False)`
(마이그레이션 `users/0004_alter_user_username.py`)

| 파일 | 줄 | 하는 일 |
|---|---:|---|
| `llm_core/negotiation.py` | 52 | SSE 용 렌더러 + 협상 우회 (위 ②) |
| `scripture/migrations/0002_seed_scripture_data.py` | 98 | `migrate` 만으로 은하 13 · 구절 702 적재 |

| `scripture/admin.py` | 24 | 은하 · 구절 |

### 시드를 마이그레이션에 넣은 이유

`migrate` 는 표만 만들고 데이터는 넣지 않습니다. DB 를 초기화하고 `migrate` 만
돌리면 표는 생기는데 안이 비어, 화면에서 별을 눌렀을 때
**"찾을 수 없는 별입니다"** 가 뜹니다.

이건 사람이 명령 하나를 잊어서 생기는 문제가 아니라, **잊을 수 있게 만들어 둔
설계**의 문제입니다. 실제로 DB 를 초기화할 때마다 밟았습니다.

빈 DB 로 확인했습니다.

```
Applying scripture.0002_seed_scripture_data... OK
→ 은하 13 / 구절 702   (seed 명령 없이)
```

세 가지를 지켰습니다.

- **여러 번 돌아도 안전** — `update_or_create` 라 덮어쓸 뿐 지우지 않습니다
- **되감아도 구절을 지우지 않음** — 지우면 그 구절을 참조하던 대화가 함께 끊깁니다.
  마이그레이션을 되감는 것과 사용자 데이터를 버리는 것은 다른 일입니다
- **`apps.get_model` 사용** — 모델을 직접 import 하면 나중에 필드가 바뀔 때
  과거 마이그레이션이 깨집니다

### 관리자 화면을 연 이유

`admin.py` 세 개가 전부 비어 있어서 관리자 화면에 **아무것도 보이지 않았습니다.**
"가입이 DB 에 저장됐는지" 확인할 방법이 없었습니다 — Swagger 는 API 문서일 뿐
DB 를 보여 주지 않습니다.

대화방을 열면 주고받은 말이 인라인으로 펼쳐집니다. LLM 답변이 제대로 저장됐는지
확인할 때 이게 가장 빠릅니다.

## 3. 고친 파일 7개

| 파일 | 무엇을 |
|---|---|
| `llm_core/services.py` | 지연 생성 (①), 모델명 상수화 |
| `chat/views.py` | 팀 수정본 반영 + `ChatStreamView` 협상 설정 (②) |
| `chat/urls.py` | 팀 수정본 반영 — `stream/` 추가, `threads/` 제거 |
| `users/models.py` | MBTI 필수화, username unique 해제 (③) |
| `users/serializers.py` | 16유형 검증 + 대문자 변환, `UserUpdateSerializer` 복구 |
| `config/settings.py` | `OPENAI_API_KEY`, CORS 포트 추가 (운영 설정은 보존) |
| `tests/test_integration.py` | 새 계약에 맞춰 갱신 + SSE 케이스 신설 |

### `UserUpdateSerializer` 를 되살린 이유

받은 `serializers.py` 에는 이게 없었고, `UserSerializer` 는
`read_only_fields = fields` 입니다. 그대로 PATCH 에 쓰면
**200 을 돌려주면서 값은 바뀌지 않습니다.** 화면에서는 저장된 것처럼 보이고
새로고침하면 되돌아갑니다. 가장 찾기 어려운 종류의 버그입니다.

### `settings.py` 를 통째로 덮지 않은 이유

받은 파일을 그대로 쓰면 아래가 사라집니다. 전부 **되돌리면 고장 나는** 항목입니다.

| 항목 | 없으면 |
|---|---|
| `scripture` 앱 | 은하 · 구절 API 전멸 (프론트가 호출 중) |
| `SECRET_KEY` 기본값 | `.env` 없으면 `git clone` 후 즉시 크래시 |
| `DATABASE_URL` SQLite 폴백 | 위와 같음 |
| `ALLOWED_HOSTS` env 주입 | `DEBUG=False` 로 켜면 전 요청 400 |
| `STATIC_ROOT` | `collectstatic` 실패 |
| `DEFAULT_AUTO_FIELD` | 매 `makemigrations` 마다 W042 경고 |
| Throttle / Pagination | API 남용 제한 없음 |
| `SECURE_PROXY_SSL_HEADER` | ALB 뒤에서 HTTPS 인식 실패 |

팀 파일에서 **추가된 것만** 얹었습니다 — `OPENAI_API_KEY`, 3000 포트 CORS.

## 5. 검증

### 서버 테스트 25개 (21 → 25)

기존 6개가 병합 전 계약(`/chat/threads/`, MBTI 선택)을 보고 있어 갱신했고,
아래를 새로 넣었습니다.

- **`Accept: text/event-stream` 으로 부르기** — 이게 없어서 406 을 놓쳤습니다
- 스트림 실패해도 사용자 메시지는 남는가
- MBTI 소문자 입력 → 대문자 저장
- 같은 이름으로 두 명 가입

### 실서버 스모크 12항목

가입(소문자 MBTI 포함) · 로그인 · `PATCH /me/` · 대화방 · 메시지 ·
**남의 대화방 403 차단** · 비로그인 401 · 은하 목록 ·
**키 없이 SSE 호출 시 서버 생존** — 전부 통과.

```

✓ career   ✓ fear   ✓ forgiveness ✓ guilt
✓ hope     ✓ gratitude ✓ recovery ✓ purpose      → 12/12
```
