# Eden — 기능 명세와 디렉토리 구성

발표용 정리. 프론트엔드 · 백엔드 · GraphDB 세 갈래로 나눈다.

---

## 0. 한 문장 요약

> 성경 31,077절을 벡터로 임베딩해 pgvector 에 넣고, 감정·인물 관계는
> Neo4j 그래프에 두어, 사용자의 고민에 맞는 구절과 그 구절을 지나간
> 인물을 함께 찾아 주는 상담 웹 애플리케이션.

---

## 1. 기술 스택

| 층 | 기술 | 왜 이것인가 |
|---|---|---|
| 프론트 | React 19 · TypeScript · Vite | 타입이 경계를 지켜 준다. 화면이 캔버스 중심이라 프레임워크는 얇을수록 좋다 |
| 렌더 | Canvas 2D (WebGL 아님) | 별 2,652개 규모에서는 2D 로 충분하고, 저사양·모바일 폴백이 단순하다 |
| 백엔드 | Django 5.2 · DRF | 인증·ORM·관리자 화면이 기본으로 온다 |
| 인증 | SimpleJWT | Access/Refresh 자동 갱신 |
| LLM | LangChain + OpenAI | 프롬프트·히스토리·스트리밍 조립을 한 곳에 모은다 |
| 임베딩 | qwen3-embedding:8b (Ollama, EC2 GPU) | 자체 구동. 외부 임베딩 API 비용과 지연을 없앤다 |
| 벡터 DB | PostgreSQL + pgvector (RDS) | 관계형 데이터와 벡터를 한 DB 에 둔다 |
| 그래프 DB | Neo4j Aura | 감정·인물·사건 관계 |
| 배포 | AWS EC2(g4dn.xlarge) · RDS · Docker Compose · nginx | GPU 가 필요해 EC2, DB 는 RDS 로 분리 |

## 2. 프론트엔드

### 2.1 화면 흐름

```
인트로 ──▶ 홈 ──▶ 답변 ──▶ 별자리 ──▶ 구절 상세 ──▶ 상담
 (창세기)  (질문)  (구절 3)  (은하 여행)   (오버레이)   (대화)
```

### 2.2 기능 목록

**은하수 렌더링 (`galaxy/`)**

- 단일 `requestAnimationFrame` 루프. React 렌더와 분리돼 있어 상태가 바뀌어도 애니메이션이 끊기지 않는다
- 프레임당 새 객체를 만들지 않는다 (GC 정지 방지)
- 3D 궤도 카메라 — yaw · pitch · distance. 드래그로 시점 회전
- 은하 13개가 공전·자전. 별 2,652개를 은하별로 배치
- **별마다 다른 주기로 밝기가 흔들린다** (`twinkle.ts`) — 같은 밝기면 하늘이 아니라 전구판이 된다
- 별 클릭 픽킹, 키보드 순회(roving tabindex + 방향키)
- 카메라 비행 — 별을 고르면 1.6초 동안 날아간다. 방향감 스트리킹
- **조우 연출** — 은하에 도착하면 별들이 그 제자의 상징(십자가·열쇠·조개…)으로 모인다
- 성운 먼지 레이어, 별자리 연결선
- reduced-motion 대체 연출, FPS 자동 강등, 캔버스 미지원 폴백

**상태 관리 (`state/`)**

Context + reducer. Redux 를 쓰지 않은 이유는 전역 상태가 다섯 갈래뿐이고,
각각이 서로를 거의 안 보기 때문이다.

| Context | 무엇을 들고 있나 |
|---|---|
| `AuthContext` | 로그인 사용자, 토큰 |
| `GalaxyContext` | 카메라 목표, 포커스 별, 호버 |
| `CounselContext` | 대화 상태 (reducer) |
| `VersesContext` | 구절 목록 (한 번만 받아 캐시) |
| `ThreadsContext` | 지난 상담 목록 |
| `EncounterContext` | 조우 연출 단계 |
| `AppPhaseContext` | 화면 단계 (인트로/탐색/상담) |

**비동기 처리 (`services/`)** ← 평가 항목

- `fetch` + `async/await`. axios 를 쓰지 않는다 — 의존성 하나를 줄이고 표준에 붙는다
- **Access 토큰 자동 갱신** — 401 이 오면 한 번만 refresh 후 재시도. 동시 요청은 한 갱신을 함께 기다린다
- **SSE 스트리밍** — 답변이 글자 단위로 흘러온다. `ReadableStream` 직접 파싱
- **요청 타임아웃** — 기본 15초, 완성 응답 45초, 스트리밍은 무제한
- **취소와 시간 초과를 구분** — 둘 다 `AbortError` 로 오지만 사용자에게 할 말이 다르다
- **화면 이탈 시 스트림 중단** — 떠난 대화에 조각이 계속 밀려들지 않게
- 원인별 오류 문구 — 시간 초과 / 연결 끊김 / 서버 오류
- mock ↔ 실제 API 를 환경변수 한 줄로 교체 (`RepositoryProvider`)

**LLM 상호작용 상태** ← 평가 항목

| 상태 | UI |
|---|---|
| 입력 전 | 입력창 활성, 추천 질문 칩 |
| 전송 직후 | 입력창 비활성, "마음을 살피는 중…" + 점 세 개 |
| 스트리밍 중 | 글자가 차례로 붙는다. 복사 버튼은 숨김(잘린 문장 방지) |
| 완료 | 복사 버튼 노출, 입력창 재활성 |
| 오류 | 원인별 문구 + 다시 시도 버튼 |

**접근성**

- 키보드만으로 전체 탐색 가능 (별 목록 방향키 순회 포함)
- `aria-label` · `role="log"` · `aria-live="polite"`
- 포커스 트랩 (사이드바·구절 목록 창)
- `prefers-reduced-motion` 대응
- 명도 대비 확보 (흑백 기조)

**반응형** ← 평가 항목

- Flex/Grid 기반. `clamp()` 로 여백이 화면 폭을 따라간다
- 브레이크포인트: 640px · 720px (MBTI 레일 접힘) · 세로 620px
- `dvh` 사용 — 모바일 주소창이 접힐 때 `vh` 는 높이를 잘못 잡는다

### 2.3 테스트

**53개 파일 / 761개 테스트** (vitest + Testing Library)

### 3.3 검색 — 네 층

```
① 벡터   pgvector 코사인 거리로 후보 60개
② 성격   tone 게이트 — 경고·질책 구절을 아예 뺀다
③ 주제   사람이 배정한 주제와 일치하면 +0.06
④ 그래프 같은 감정을 겪은(+0.015) / 이겨 낸(+0.04) 인물이 등장하면
```

**왜 벡터만으로 부족한가** — 번아웃을 검색하면 잠언 24:10 "네 힘이 미약함을
보임이니라" 가 올라온다. 낙심을 말하는 구절이라 문장은 비슷하지만 위로가
아니라 질책이다. 그 차이는 본문이 아니라 관계가 안다.

### 3.4 프롬프트 — 세 층

```
공통 규범 (common.py)    ← 13명 전원 동일. 안전 · 상담 태도 · 이탈 · 욕설
    +
관계 맥락 (relations.py) ← 열둘만. 제자 사이의 관계
    +
개별 인물 (personas.py)  ← 13명 각각
    +
대화의 바탕              ← 씨앗 구절 + 그래프 인물 (chat/context.py)
```

순서가 곧 우선순위다. 안전이 맨 앞이라 페르소나가 그것을 덮을 수 없다.

**턴 지시** — 몇 번째 답변인지는 서버가 세서 알려 준다. "두 번째 답변부터
인물을 꺼내십시오" 를 프롬프트에 적었더니 지켜지지 않았다 — 모델더러
히스토리를 보고 턴을 세라는 뜻인데, 그건 모델이 잘 못하는 일이다.

### 3.5 데이터 파이프라인

```
bible_structured.json (31,077절)
   │ ingest_bible
   ▼
BibleVerse ──── ingest_bible --embed ───▶ embedding (pgvector)
   │
   │ assign_galaxies --by-embedding --canvas 150
   ▼
usable(28,424) · galaxy_id · on_canvas(1,950)
```

관리 명령: `ingest_bible` · `assign_galaxies` · `seed_scripture` · `graph_probe`

### 3.6 안전 설계

- 자해·자살·학대·위기 신호가 보이면 **위로보다 먼저 안전을 확인**
- 프론트에서도 판정해 서버를 기다리지 않는다 (서버가 죽어도 안내는 뜬다)
- 신학적 단정 금지, 의료·법률 전문 조언 금지
- 예수 표현은 빛·음성·상징으로 (얼굴·신체 묘사 없음)

### 3.7 테스트

**334개 통과** (pytest + pytest-django)

## 4. GraphDB (Neo4j Aura)

### 4.1 규모

- 인물 **2,861명**
- 감정 연결 **29,813개**
- 구절 **31,077개** (`ref` = `"창 1:1"` 형식이 고유 키)

### 4.2 스키마 (우리가 쓰는 부분)

```
(Verse {ref, content})-[:MENTIONS]->(Person {name})
(Person)-[:EXPERIENCED]->(EmotionOrState {name, theme, category})
(Person)-[:OVERCAME]->(EmotionOrState)      ← 회복된 상태가 목적지
(Galaxy {id})-[:CURATES]->(Verse)
```

`EmotionOrState.theme` 이 우리 `intents.json` 코드와 **같은 값**이다.
질문에서 뽑은 주제를 그대로 넣을 수 있고, 이것이 벡터와 그래프를 잇는
유일한 다리다.

### 4.3 쓰는 방식 두 가지

**① 검색 가산점** (`graph.boost`)

질문의 주제와 같은 감정을 **겪었거나 이겨 낸** 인물이 등장하는 구절을 올린다.
`OVERCAME` 에 두 배 이상을 주는 이유는, 그것이 드물어서 신호가 되기 때문이다.

**② 상담 맥락 주입** (`graph.theme_witnesses`)

질문의 감정을 지나간 인물을 프롬프트에 넣는다.

```
[이 감정을 지나간 사람들]
룻: 충성 → 사랑과 가족의 회복
이삭: 사랑, 위로 → 하나님과의 확신과 평안
```

사실만 주고 해석은 안 붙인다. "그러니 당신도 이겨 낼 수 있습니다" 를 우리가
쓰면 그건 그래프가 아니라 우리 문장이 된다.

### 4.4 허브 제외 — 측정으로 정한 값

처음에는 "테마 개수" 로 허브를 걸렀다가 틀렸다.

```
여호와  6,020절  테마 12   ← 빠진다
예수    1,877절  테마 10   ← 빠진다
─────────────────────────  HUB_MENTION_LIMIT = 1000
이스라엘  982절  테마 11
다윗      928절  테마 11   ← 남는다 (시편의 절반, 좋은 신호)
베드로    163절  테마  9
```

여호와가 쓸모없는 이유는 감정이 많아서가 아니라 **어디에나 있어서**다.
재야 할 것은 감정의 폭이 아니라 등장 범위였다.

### 4.5 실패에 열린 설계

Aura 가 느리거나 죽거나 스키마가 달라도 **모든 그래프 함수는 빈 값을 돌려준다.**

- 연결 3초 · 질의 2초 타임아웃
- 예외를 위로 던지지 않는다
- 그래프가 없으면 벡터 + 주제 + 성격만으로 검색이 돈다

발표 중에 Aura 세션이 만료돼도 사용자는 눈치채지 못한다 — 답이 조금 덜
풍부해질 뿐이다.

### 4.6 쓰지 않는 것

`Verse.embedding` (1536차원)과 벡터 인덱스가 그래프에도 있지만 쓰지 않는다.
우리 pgvector 는 qwen3-embedding:8b 로 만든 **다른 공간**이다. 두 공간의
점수를 섞으면 숫자는 나오지만 뜻이 없다. 벡터는 Postgres 가, 관계는 Neo4j 가 맡는다.

### 왜 이렇게 나눴는가

**`galaxy/` 가 `components/` 밖에 있다** — 렌더 엔진은 React 컴포넌트가 아니다.
단일 rAF 루프로 돌고 React 렌더 주기와 무관하다. 같은 폴더에 두면 "이것도
컴포넌트겠거니" 하고 상태를 밀어 넣게 된다.

**`services/` 가 인터페이스와 구현을 나눈다** — `repositories.ts` 가 계약이고
`mock*` / `http*` 가 구현이다. 화면 코드는 계약만 안다. 백엔드가 없어도
화면 전체가 돈다.

**`llm_core/` 가 `chat/` 밖에 있다** — 프롬프트는 대화방의 일부가 아니다.
`scripture` 의 추천도 같은 인물 정의를 쓴다.
