### 1.1 목적
본 테스트 계획서는 Django & React 기반 LLM 챗봇 서비스 웹 애플리케이션의 주요 기능, 비기능 요소, LLM 비동기 연동 예외, Docker 기반 배포 안정성을 종합 검증하여 시스템의 안정성과 품질을 확립하는 것을 목적으로 한다.

### 1.2 범위
- **대상 시스템**: LLM 연동 웹 애플리케이션 (배포 환경: `http://3.37.228.101/`)
- **테스트 범위**:
  - 사용자 인증 및 계정 관리 (회원가입, 로그인, 세션 유지)
  - 웹 UI/UX 및 반응형 화면 구현 검증
  - LLM 모델 연동 (스트리밍, 비동기 통신, API 타임아웃 및 토큰 초과 예외 처리)
  - 배포 환경 검증 (Docker 컨테이너 재현성, 서버 재기동 후 볼륨 지속성)
  - 백엔드 API 연동 및 DB CRUD 검증

## 2. 테스트 목표 및 기준
### 2.1 성공 기준 (Pass Criteria)
- **기능 커버리지**: 핵심 시나리오(회원가입/로그인, LLM 대화 요청/응답, 대화 이력 CRUD) 100% 정상 수행
- **LLM 응답성 및 예외 처리**: 정상 질의 시 3초 이내 스트리밍 시작, 비동기 에러(타임아웃, 토큰 초과) 발생 시 예외 안내문 정확히 표출
- **배포 안정성**: Docker 컨테이너 재기동 후 DB 데이터 유지 및 서비스 정상 자동 복구

### 2.2 실패 기준 (Fail Criteria)
- 웹 서버 응답 불능 (500 Internal Server Error, 502 Bad Gateway 등)
- LLM API 연동 실패 시 화면 무한 로딩(Hanging) 현상 발생
- 서버 재기동 시 데이터베이스 저장 기록 손실

## 3. 테스트 환경
- **서버 환경**: AWS EC2 Linux, Docker, Docker-Compose, Nginx, Django REST Framework, PostgreSQL
- **LLM API**: OpenAI API / vLLM 연동
- **클라이언트 환경**: Chrome, Edge, Safari (PC/Mobile)

### 4.2 LLM API 연동 및 비동기 예외 테스트
| ID | 테스트 항목 | 사전 조건 | 테스트 절차 | 예상 결과 |
|---|---|---|---|---|
| TC-LLM-01 | 기본 질의응답 | 로그인 상태 | 대화창 입력 후 전송 | LLM 정상 답변 생성 |
| TC-LLM-02 | SSE 스트리밍 출력 | 로그인 상태 | 긴 답변 유도 질의 전송 | 실시간 스트리밍 렌더링 |

| TC-LLM-04 | 토큰 한계(Context Limit) 초과 | 로그인 상태 | 초장문 프롬프트 전달 | Token Limit 초과 예외 메시지 표출 |
| TC-LLM-05 | 네트워크 중단 예외 | 스트리밍 중 | 응답 수신 중 클라이언트 네트워크 단절 | 재연결 안내 및 대화 상태 안전 종료 |

### 4.3 배포 환경 검증 (Deployment & Infrastructure)
| ID | 테스트 항목 | 테스트 방법 | 예상 결과 |
|---|---|---|---|
| TC-DEP-01 | Docker 컨테이너 재재현성 | `docker-compose down && docker-compose up -d` 실행 | 컨테이너 빌드 및 정상 서비스 재개 |
